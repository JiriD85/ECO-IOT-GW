# Management UI function audit — 2026-09-10

Scope: traced the Vue views through `frontend/src/services/api.js`, FastAPI routers in `backend/app/api`, and their service implementations. This is a repository wiring and usefulness audit, not certification of hardware actions. The local preview supplies fixtures and rejects hardware changes; rendering it does not prove an action works on Linux. No hardware settings, services, containers, or deployment were changed during this audit.

## Original findings (resolved below or awaiting hardware acceptance)

1. **Watchdog state is inconsistent.** `watchdog_service.get_status()` hard-codes `openvpn-client@client` for the VPN row, while recovery uses the selected VPN service. Enable/disable calls start/stop the thread without persisting `WatchdogConfig.enabled`; application startup starts it unconditionally. This control is not a reliable persistent setting yet.
2. **Modem profile ownership needs verification.** APN configuration recreates `gsm-connection`. Establish whether provisioning uses that profile, and preserve the existing connection where appropriate before testing on a metered remote link.
3. **Backup is partial and does duplicate work.** `BackupService.BACKUP_PATHS` includes selected `/etc` directories and audit data, but not all `/var/lib/eco-iot-gw` application configuration (e.g. saved ThingsBoard/branding data), NetworkManager profiles, or Tailscale state. Creation currently compresses an archive, deletes it, then creates it again to update the manifest. Coverage and restore behavior need focused tests; this audit did not expand restore privileges or change archive format.
4. **Legacy serial write API remains.** The UI no longer offers its misleading settings/test controls, but `/api/serial/config` PUT and `/test` still exist for compatibility. They need retirement or a deliberate active-connector implementation before being exposed again.
5. **Legacy update APIs remain.** Update discovery is a placeholder; rollback is not guaranteed to restore application code. Removed their UI entry points rather than imply a supported release workflow.
6. **Status failure semantics need another pass.** Several management views log fetch failures without a visible error; some backend connectivity failures become all-false status. A failed status request can therefore resemble a stopped or disconnected service. The primary live dashboard handles stream loss separately, but management pages are not uniformly corrected.
7. **Daemon-backed features require actual service evidence.** Failover and SMS have separate systemd units in this repo. Their configuration forms alone do not establish installation, runtime health, or successful recovery/alerting on the kit.

The unused `/api/diagnostics/modbus/poll` endpoint also falsely returned “Poll request sent” without polling anything. It now returns HTTP 501 instead of claiming success.

## Recommended navigation consolidation

Keep **Dashboard**, **Network**, **ThingsBoard**, and **System** as primary destinations. Network can contain cellular, failover and VPN. Move Connector/serial inventory, Diagnostics/logs, Audit, SMS, Containers and Terminal under Advanced. This is a proposed next structural pass, not a claim that all navigation has already moved. Preserve existing deep links with redirects when implementing it.

Avoid removing VPN, backup, audit or recovery tools just because they are infrequently used: they have distinct service functions. Remove duplicate readouts and unsupported controls first. No new polling, graph library, font or icon dependency was added by this audit.


## Follow-up implementation — release 2.0.0

- Watchdog settings are persisted atomically and honored at startup. Its worker can be stopped promptly during its wait and cannot be started twice by concurrent requests. The status row uses the selected VPN; no configured VPN means no recovery action.
- Cellular operations discover the active GSM profile by UUID, reject ambiguous inactive profiles, and modify it in place. Routing metrics and unrelated profile settings are retained. Masked password/PIN fields preserve the saved credentials. Command failures no longer report success.
- Configuration backups include the migrated `/opt/eco/tb-gateway/config`, UI branding, application configuration, VPN and NetworkManager profiles. A single compression pass includes checksums; validation rejects paths outside an explicit allowlist, links, special files, duplicates, and excessive size. Restore validates all content before writing, uses atomic file replacement, and attempts to restore prior file contents if a write fails. Reboot is required to apply restored configuration. This is not a disk image: audit history, OS accounts and live Tailscale identity are deliberately excluded.
- Management HTTP read failures now produce a persistent page-scoped error with retry. Blocking modem, watchdog and ThingsBoard handlers use FastAPI's threadpool so they do not block live WebSocket traffic.
- Legacy serial writes/tests return 410; unsupported OTA update/rollback operations return 501. The supported installer is `provisioning/migrate/tui.js`.
- ThingsBoard reads the installed gateway connection configuration. Saving supported host/port/credential changes preserves hidden credentials, connector registration, polling and statistics. Existing TLS configuration is preserved; TLS/certificate migrations are explicitly rejected pending validation of the pinned image's TLS behavior. Start/Stop operate on the existing container rather than generating a replacement Compose stack. The misleading generated Compose preview was removed from the page.
- The TUI checks a source revision and artifact hashes instead of accepting any cached bundle/running backend. It builds changed sources, upgrades the observer using the exact installed image and retained runtime settings, and records the installed revision only after success. The web installer keeps prior application files and hashed assets, checks `/api/health`, and restores prior files if the new application fails that check.

Still requiring kit acceptance: actual LTE reconnect, reboot persistence, restore/reboot, Modbus decoding/disconnection behavior with real sensors, and continued ThingsBoard delivery. Separate SMS/failover daemon installation and runtime behavior remain outside these mocked service tests. No hardware was accessed or changed during this follow-up.
