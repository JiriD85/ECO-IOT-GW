ECO telemetry — one converging node map

Two ingest paths, one destination. Field units are migrating from proprietary RESI software to standard ThingsBoard tb-gateway (ECO GW) software — in parallel, non-breaking. Below, both paths live on a single canvas: they diverge at the top and merge into one shared trunk that is drawn once. Left path sourced strictly from TELEMETRY_PIPELINE.md; right path is the migration design.

Headline: both paths feed the exact same Switch to Measurement gate → Measurement asset → Calculated Fields → alarms → dashboards. The RESI path threads a long split/rename/normalize chain to get there; the ECO GW path collapses that whole middle to a single hop, because the Modbus connector emits canonical, pre-scaled keys and the platform splits v1/gateway/telemetry per child device.

Unified pipeline node map — two entries converge to one trunk

RESI device/asset profiles stay bound to their Doktorkit / RESI chains (untouched, ~700 live devices). GW profiles (P-Flow D116 GW, Temperature Sensor GW, ECO GW) get the new minimal chain, and a cloned Measurement GW asset profile carries the two extra CFs so dT_K does not collide with RESI's Normalize output. Both paths meet at the single amber Switch to Measurement gate and share everything below it.
